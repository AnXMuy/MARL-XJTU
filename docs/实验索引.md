# 实验记录索引

报告写作时优先引用主报告第10节与冻结方案复验；不要把探索日结果混成独立确认结果。

|研究问题|配置与证据|结论口径|
|---|---|---|
|MAPPO是否优于IPPO|`results/layout/`、`assets/metrics.json`、`assets/report_figs/seed_summary.json`|同actor输入；三个MAPPO种子、一个IPPO种子，不足以证明集中critic普遍占优|
|扩大网络是否有效|`results/capacity/*/run_manifest.json`、`validation.json`、`throughput.json`|相同30M预算256/512对照，不能与旧20M简单比较后归因容量|
|扩容测试指标|`assets/capacity_metrics.json`、`assets/capacity_control.json`|同20个探索日、四场景；模型选择由验证回报决定|
|联合功率分配|`assets/architecture_study.json`|集中执行层，不冒充新MARL训练算法|
|短时域MPC|`assets/architecture_study.json`、`assets/mpc4h_study.json`|有限束宽模型基线；不是全局最优、不是学习策略|
|策略前瞻时域|`assets/lookahead_selection.json`、`assets/lookahead32_validation.json`|验证选择1/2/4/8h，非测试日挑选|
|探索集前瞻结果|`assets/lookahead_study.json`|4h版本，探索日100000–100019，不作为8h最终结果|
|冻结方案复验|`assets/final_study.json`|8h版本，新日100020–100039，原始轨迹、模型SHA256与配对区间|
|导出是否忠实|`assets/evidence/export_check.txt`、`training/verify_export.py`|原BenchMARL策略与导出actor动作一致；不包括集中执行层|
|环境与交互验收|`assets/evidence/tests.txt`、`assets/demo/browser_check.json`|自动测试数量以发布验收日志为准；浏览器语音为事件注入，不是声学测试|
|展示视频|`assets/demo/paired_day.mp4`|历史户型可视化：新复验第一天真实保存动作；不是当前数据表前端录屏|

数据单位：电费CNY、能量kWh、功率kW、有人区域超出±1℃容忍带后的温度偏离°C·h。降低电费不等于降低耗电量：峰谷移位可能降低费用但增加总能量。两者必须分别报告。

已知限制：四区冬景RC仿真、理想天气/人员预测、前瞻集中执行、未完成多训练种子的混合架构复验、未做严格同舒适阈值成本曲线、未做真实建筑或实际麦克风声学部署验证。不得将模拟结果写成真实节能承诺。

报告主要论点应是“偏好解耦、约束执行、模型前瞻的组合及其控制权衡”，而非“加宽网络必然有效”或“所有情形节费15%”。与原策略比较时应保持同权重；与规则比较时应同时给出舒适与费用，不利用规则的低舒适来夸大节电。
