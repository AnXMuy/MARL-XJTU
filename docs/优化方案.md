# MARL-Home 重构：让协同控制成为项目主体

> 历史设计记录：本文保存最初重构时的判断，界面等阶段性方案已被后续实现替代。当前方法、指标与交互以[技术报告](技术报告.md)、[复现指南](复现指南.md)和根README为准。

## 项目现在应该回答的问题

四个房间共享一份供暖用电容量。天气、人员位置、电价和用户目标不断改变时，各房间能否通过学习，在较低费用下保持有人空间舒适，并减少同时抢功率？

语言交互是改变目标的入口，不是创新的全部；ASR、LLM、TTS 不应吞掉主体工作和展示时间。可陈述的贡献是：**可变偏好条件下的多区域需求响应控制、可复现的合作收益评估、可解释的交互呈现**。不能声称首次把语音与 MARL 结合，也不能把自建低阶模拟器上的结果写成真实建筑节能成果。

## 原方案为何差

1. **任务没有充分的合作冲突。** 原来只是四个房间的奖励相加，房间间很弱的热耦合；缺少共同功率预算等协调目标。
2. **模型输入与目标错位。** 睡眠会覆盖实际目标，但输入仍主要是原始温差偏好；没有显式有效目标和即将到来的占用需求。
3. **训练目标与报告不一致。** 无人房间仍被温差惩罚，离家应关断与奖励冲突；“任一房间违规则全步违规”受人数影响，无法准确衡量舒适损失。
4. **QMIX 并未经过任务适配比较。** 单调性有工程优势，但遇到共同功率下的相互取舍，未必是合适的表示。此前训练失败不能全部归罪于算法，也不能靠盲目追加步数解决。
5. **算力路径不合理。** 串行 Python 环境 + CPU MLP64 没有利用现有 GPU。网络小本身不是错误，未做批量训练和容量对照才是缺失。
6. **展示缺少因果链。** 原始 JSON、两个矩形图和一条费用曲线不能说明房间为什么协作；“节省15%”也不是可保证的实验结论。

旧冒烟模型费用明显高于规则，旧正式运行已停止，保留压缩后的历史指标用于追溯。旧环境和新环境不同，禁止用两者的费用直接计算提升。

## 实际训练框架与网络

主线已从 EPyMARL 迁移到 **BenchMARL 1.5.2 + TorchRL 0.11.1 + TensorDict 0.11.0**：真正调用其 Experiment、GPU collector、MultiAgentMLP、GAE、ClipPPOLoss 和优化器。不是自行写一个 PPO 再贴框架名。

- 主算法：MAPPO，集中训练、分散执行；四房间共享策略参数，房间 ID 区分角色。
- actor：33维观测 → 256 → 256 → 256 → 9个动作 logits，Tanh。
- critic：全屋四房观测 → 512 → 512 → 512 → 团队价值。
- 9动作对应3档供暖×3档照明，动作完全由网络输出，无启发式后处理。
- IPPO 消融：相同 actor、相同观测、相同奖励和训练预算，仅换为各房本地价值网络。公共需求汇总广播对两者都可见，集中 critic 在执行时不用。
- 1024个并行家庭完全在GPU上仿真；96步/批，每批98304环境转移，6轮更新，8192 minibatch，Adam3e-4，gamma.99，lambda.95，clip.2，梯度裁剪.5。
- 采用固定奖励缩放1/5以稳定官方价值损失。早期自写MAPPO试验使用过PopArt与分解动作头；旧实现已清理，**不作为当前BenchMARL结果的实现描述**。
- 每次导出写入环境版本、结构和训练参数。推理只载入 actor 的真实权重，另有与框架逐步贪心动作一致性验证，避免训练/推理两套模型悄然不一致。

更宽网络不是先验保证。独立 PPO 已纳入实验；更大网络容量对照仍待后续实跑。若 MAPPO 无法超过强规则或 IPPO，就如实报告并继续定位；不会为证明合作而削弱基线。

## 可信而可控的任务

当前环境命名 `coordinated-home-v3.0`，不改变v1的解释。四区 RC 近似明确热容量、传热系数、COP、15分钟能量积分。内区传热对称守恒。当前仍是冬季供暖模型，未模拟湿度、日照、设备延时、真实建筑参数辨识。

全屋可控负荷容量4kW；奖励包含有人房间的温度超容忍带、照明不符、电费、超容量平方惩罚，以及12–30℃物理安全范围的软惩罚。容量和安全均为**软约束**，没有安全保证，违规必须显示。无人房间不以舒适目标逼迫供暖，低温保护另算。

观测直接给有效目标、温度误差、当前/一小时后占用、当前/未来电价、时间、场景、省电权重与公共需求摘要。偏好训练随机化，30%的家庭中途改目标。用户温度偏好在睡眠场景也可继续编辑，不再被硬编码20℃永久覆盖。

## 实验如何讲得站得住

- 基线A：占用感知恒温器、灯随人走、无电价意识。
- 基线B：协调规则，提前一小时预热、电价切换感知，并在同一功率上限内按需求分配。它是强基线，不以无约束弱规则作为唯一对手。
- 消融：同预算 IPPO；模型容量消融尚未执行。
- 测试日种子100000起，与验证种子900000分离；默认、省电、睡眠、中途连续指令四组。所有控制器共用天气、日程、初始温度、偏好更新。
- 指标：费用、kWh、有人区超温带degree-hours、有人区违规时长比例、峰功率、超容量kWh、照明不符与团队回报。**费用和能耗分开**，移峰可能降低费用但增加kWh。
- 成对日差bootstrap95%区间；训练种子的均值与标准差单独统计，不能用测试日置信区间冒充训练稳定性。
- 不预设必降15%。费用下降但舒适明显变差不能称成功，睡眠场景更贵也不能隐去。

## 展示主线

界面主体为双户型：左学习策略、右协调规则，相同测试日同步推进。每个房间显示实际温度、有效目标带、占用、供暖功率和灯光；全屋功率条标出4kW上限。上方并列费用、舒适偏离、超容量、电价，任何变差都直说。

三分钟讲解建议：先观察白天低价准备；回家提高客厅需求；晚高峰观察四房共享功率；切睡眠让卧室目标接管。使用时间线标注指令，解释“改目标→网络重新决策→动作改变→热惯性下逐渐接近目标”，不能宣称动作代表神经网络可证明的内部理由。

交互支持文本、场景按钮、暂停、逐步推进和跑完一天。每个浏览器会话独立环境。持续语音采用浏览器识别接口，可选本地LLM。自动化测试区分注入识别事件与真实声学识别，不把前者冒充后者。

## 后续研究价值

在本任务验证后，可增加多季节参数随机化、变化功率上限、通信消融、注意力critic、部分可观测GRU，以及Sinergym/EnergyPlus外部验证。先证明每一步改善，再扩大模型和仿真复杂度。48G显存应服务于更大批量和多种子试验，而不是无意义缓存。

## 四区户型扩展

每区面积16–36㎡，用户指定对称传热门图。面积决定热容量及外墙传热系数；门图进入能量守恒的区间传热。观测新增本区面积和门图行，维度38，训练时随机化。旧33维权重被环境版本检查拒绝。UI中的房间轮廓用于表示面积比例，不是精确CAD几何；任意数量房间、多楼层与真实建筑泛化未实现。
