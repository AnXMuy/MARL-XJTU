# 实验协议（正式矩阵 v1）

- 问题：相同需求场景下，IPPO/MAPPO 相对 Fixed-time、Max Pressure 的交通指标差异如何随需求负载变化？
- 主指标：600 s 内逐秒全网停车车辆数累加，再除以计划发车数（秒/车）；不包含路网外等待，不对时间窗后的等待外推。以相同测试 route seed 的方法间配对差值为主分析。
- 次指标：平均旅行时间、完成车辆数/吞吐量、仿真结束时未完成车辆数、时间平均网络排队长度、最差路口等待/队列、相位切换次数。
- 路网：固定 4×4 受控网格，5 s 决策、3 s 黄灯、5 s 最小绿、0 s 全红。
- 场景：300 s 注入，600 s 全窗口计量，无单独 warm-up。C1/C2/C3 注入周期 1/0.5/0.25 s。容量预试 seed 71/72，训练需求 101–103，测试需求 1000–1009；每档用相同生成机制，只改变总体强度。
- 算法：Fixed-time、Max Pressure、共享 actor 参数 IPPO、MAPPO（训练时集中 critic；执行 actor 仅接收局部观测）。
- 消融：MAPPO 去集中 critic（IPPO），以及 MAPPO 局部队列奖励改为网络平均队列奖励。每模型固定 24 轮预算，初始化 11/22/33；不以测试表现选权重。
- 统计：学习方法每个需求先平均三个初始化，方法之间按十个需求单位配对；报告均值、样本标准差和 10,000 次成对 bootstrap 百分位 95% CI。不给未完成车辆补算完成时刻；另报车辆完成、已发未完成、未发和等待插入积分。
- 记录：每次运行保存配置、代码状态、依赖与 SUMO 版本、场景和 seed、原始逐 episode 指标、模型 checkpoint 与时间戳。

机器可读冻结协议为 `configs/study.json`；本页补录指标约束。v1 每档使用 3 个训练需求；没有独立操纵热点、事故或转向异质性，也没有稳态峰值容量结论。
